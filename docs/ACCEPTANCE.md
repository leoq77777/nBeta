## 已修正的问题

- 每队 80 场赛程却输出 82 场预测胜负的问题；按实际场次计算并展示 30 场缺口。
- `UTAH/UTA`、`NO/NOP` 等别名造成配置和资源匹配遗漏。
- 用模型或 seed 让分拼出“市场盘口”的问题；仅接受独立 `market_spread` 输入。
- 硬编码多季回测、交叉验证提升及校准数据；改为 107 场快照上的实算 prequential 指标。
- 用球员 ID 人工扰动攻防分配、用比赛 ID 人工扰动比分清洗；已移除。
- 非法模拟次数、概率总和和数据一致性缺少失败检查。
- 客队评级变化使用主队变化相反数的问题；分别导出真实更新量。
- 周变化按第八个有比赛日取值的问题；改为实际日历七天前快照。
- 排序/过滤重绘导致分区按钮失去事件处理、移动端明细表撑宽页面。

## 数据与上线边界

1. 现有种子文件来源未独立验证；最后已完赛日期为 2026-11-02。构建时间不等于数据更新时间。
2. 只有 1,200 场比赛，每队 80 场；缺失比赛未虚构，季前总胜场与局部赛程预测并非同口径。
3. 没有逐回合阵容 stints、多季市场历史、经训练的球员 RAPM/伤病生存模型。比分代理、位置分配、恢复时程和先验仍是假设，已在界面和 README 标明。
4. 没有可验真的多季交叉验证或独立样本外成绩。当前已完赛样本的实算指标为 Log Loss 0.606668、Brier 0.210492、Accuracy 0.672897；不可据此推导市场优势。
5. ESPN 伤病适配器为已有可选功能，本轮未进行真实网络集成验收；离线模式与市场空值契约已测试。NBA 官方 CDN 的探测请求收到 HTTP 403，未据此接入实时比分。
6. 同战绩使用随机抖动，未实现 NBA 官方完整排名 tie-breaker。
7. 已提供 GitHub Actions 构建/Pages 部署配置；当前没有 `.git`、remote 或 GitHub Pages 目标，无法进行真实线上部署验收。工作流定时重建快照，不宣称更新比赛结果。

## 重现

```sh
source .venv/bin/activate
python -m unittest discover -s tests -v
node --check assets/app.js
python -m pipeline.build_daily --sims 100000
python -m http.server 8765 --bind 127.0.0.1
# 另一个已激活虚拟环境的终端：
python tests/browser_check.py
```

浏览器测试依赖 `requirements-dev.txt` 与 Playwright Chromium。任何新 seed 输入都应重新构建并运行验证，不沿用本报告的数值作为新数据的结论。
